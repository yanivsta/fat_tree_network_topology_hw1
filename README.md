# Canonical k-ary Fat-Tree

This small Python project constructs and checks the three-tier, canonical
fat-tree topology used in data-center networking. It includes deterministic
topology generation, structural validation, and reproducible link-failure
injection. Network metrics, experiments, and plots are not implemented yet.

The topology follows Section 2.2, “Fat-Tree Topology,” in M. Al-Fares,
A. Loukissas, and A. Vahdat, *A Scalable, Commodity Data Center Network
Architecture* (SIGCOMM 2008), [DOI: 10.1145/1402946.1402967](https://doi.org/10.1145/1402946.1402967).

## Model

`k` is the number of ports on every switch, not the number of pods. It must be
an even integer at least 2. In the canonical k-ary Fat-Tree, this port count
also determines that the topology contains exactly `k` pods. Let `m = k / 2`.

- There are `k` pods. Each pod contains `m` edge switches and `m` aggregation
  switches.
- Each edge switch connects to `m` hosts and to every aggregation switch in its
  own pod.
- There are `m²` core switches: `m` core groups, each containing `m` core
  positions.
- The three layers are edge (host-facing), aggregation (inside a pod), and
  core (between pods). Hosts are leaves rather than a switch layer.

Nodes have readable, collision-free IDs and metadata:

- `host:p0:e1:h0`: host in pod 0, below edge switch 1
- `edge:p0:e1`: edge switch 1 in pod 0
- `agg:p0:a1`: aggregation switch 1 in pod 0
- `core:g1:c0`: position 0 in core group 1

The exact core indexing convention is important: `agg:p:a` connects to every
`core:g=a:c` for `c` from `0` to `m-1`. Thus every core switch `core:g:c`
connects to exactly one aggregation switch, `agg:p:g`, in every pod. The
position distinguishes switches within a core group; the group selects the
aggregation-switch index. This produces no host-host, edge-core, or
aggregation-aggregation links.

For each `k`, every host has degree 1, each switch has degree `k`, and the
complete graph is connected. The generator adds nodes and links in fixed loop
order, so the same `k` always produces the same graph and node IDs.

## Inputs, setup, and use

Requires Python 3.10 or newer.

```bash
python3 -m pip install -r requirements.txt
python3 main.py --k 4
```

The command-line inputs are:

- `--k K` (required): even switch-port count, with `K >= 2`. It controls the
  topology scale, including the number of pods (which is also `K`).
- `--failure-rate PERCENT` (optional, default `0`): percentage from `0` through
  `100` of eligible links to remove.
- `--failure-scope {all,fabric}` (optional, default `all`): `all` samples every
  link type; `fabric` samples only edge--aggregation and aggregation--core
  links, preserving host--edge links.
- `--seed INTEGER` (optional): makes the sampled failed-link set reproducible.
- `--draw` (optional): displays the intact topology when `k <= 4`.

For example, this removes a reproducible 25% sample from fabric links only:

```bash
python3 main.py --k 4 --failure-rate 25 --failure-scope fabric --seed 7
```

The generator first builds and validates the intact graph. Failure injection
then copies that graph and removes sampled links from the copy, so the original
topology remains available for comparison. For `N` eligible links and a rate
of `PERCENT`, the number removed is `floor(N * PERCENT / 100 + 0.5)` (nearest
integer, with `.5` rounded upward). Sampling is uniform and without
replacement.

To display an educational, layered drawing of a small topology:

```bash
python3 main.py --k 4 --draw
```

`--draw` uses Matplotlib and is deliberately available only for `k <= 4`.
Larger fat-trees have too many nodes and links for a readable on-screen diagram;
the command reports a clear error instead. The drawing uses one row and color
per role: hosts, edge switches, aggregation switches, and core switches.

If `python` on your system already means Python 3, the assignment-style command
also works:

```bash
python main.py --k 4
```

Invalid values, such as an odd `k`, are rejected clearly:

```text
main.py: error: k must be an even integer greater than or equal to 2
```

## Verification

Run the complete test suite with:

```bash
python3 -m unittest discover -v
```

The current test run completed with **11 tests passing**. It checks reference
cases `k = 4, 6, 8` (including 16/20/48 for `k = 4`), node and link formulas,
roles and metadata, host and switch degrees, graph connectivity, the exact
aggregation-to-core convention, invalid inputs, and detection of a deliberately
removed core link. It also tests 0% and 100% failure rates, rate/scope
validation, nearest-integer failure counts, preservation of the original graph,
fabric-only filtering, seed reproducibility, and CLI failure summaries.
